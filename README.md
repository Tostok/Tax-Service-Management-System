# Техническое Задание: Система Управления Налоговой Службой (DTA) 

## 1. Введение и Суть Проекта

**Название проекта:** "Digital Tax Authority" (DTA)

**Цель:** Разработать комплексную информационную систему для автоматизации деятельности налоговой службы. Система должна обеспечивать учет налогоплательщиков, прием и обработку деклараций, контроль за уплатой налогов и формирование отчетности.
*Примечание: На данной итерации фокусируемся на базовом монолитном приложении, закладывая фундамент для дальнейшего расширения.*

**Ключевые особенности:**
*   Ведение единого реестра налогоплательщиков (физические и юридические лица).
*   Обработка налоговых деклараций с автоматическим расчетом обязательств (на первом этапе - в виде структурированных данных/JSON).
*   Учет платежей, отслеживание задолженностей и пеней.
*   Гибкая система ролей и прав доступа.
*   Генерация уведомлений и отчетов.

**Команда:** до 5 человек.
**Срок разработки:** 1 учебный год.

## 2. Технологический стек

*   **Язык программирования:** Java 17+
*   **Фреймворк:** Spring Boot 3.x.x (с использованием Spring MVC, Spring Security, Spring Data JPA)
*   **База данных:** PostgreSQL (для разработки и продакшена), H2 (для локальных тестов)
*   **Контейнеризация:** Docker, Docker Compose (для локального развертывания)
*   **Документация API:** OpenAPI 3 (Swagger)
*   **Аутентификация/Авторизация:** Spring Security, JWT
*   **Логирование и мониторинг:** Logback, Spring Actuator

## 3. Функциональные требования (Минимальный Функционал - Монолитное приложение)

### 3.1. Модуль "Администрирование и Безопасность"
*   **Роли:**
    *   `ADMIN`: Управляет учетными записями налоговых инспекторов.
    *   `TAX_INSPECTOR`: Основная роль; управляет данными налогоплательщиков, обрабатывает декларации.
*   Создание, блокировка и управление учетными записями инспекторов (выполняется `ADMIN`).

### 3.2. Модуль "Управление Налогоплательщиками"
*   **CRUD:** Создание, чтение, обновление и архивация карточки налогоплательщика.
*   **Разделение:** Учет физических и юридических лиц с разными наборами полей (ИНН, ОГРН и т.д.).
*   **Поиск:** Расширенный поиск и фильтрация по ИНН, названию организации, ФИО.

### 3.3. Модуль "Обработка Деклараций"
*   **Прием:** Загрузка налоговых деклараций (в виде структурированных данных/JSON) в систему и привязка к налогоплательщику.
*   **Расчет:** Автоматический расчет суммы налога к уплате на основе данных из декларации.
*   **Статусы:** Отслеживание статуса декларации (`ПРИНЯТА`, `В ОБРАБОТКЕ`, `ПРОВЕРЕНА`, `ОШИБКА`).
*   *Примечание: На данной итерации не требуется поддержка загрузки PDF/XML. Декларации принимаются в структурированном формате (например, JSON).*

### 3.4. Модуль "Финансовый Учет"
*   **Регистрация платежей:** Внесение информации об уплате налога.
*   **Контроль задолженности:** Автоматическое сопоставление начисленных сумм (из деклараций) и поступивших платежей для выявления недоимки.
*   **Расчет пени:** Автоматический расчет пени на сумму задолженности за каждый день просрочки.

## 4. Примерная структура сущностей

*   `User` (id, username, password, role)
*   `TaxInspector` (id, user_id, full_name, department)
*   `Taxpayer` (id, taxpayer_type (`INDIVIDUAL`, `LEGAL_ENTITY`), inn, name, ...)
*   `Declaration` (id, taxpayer_id, tax_type, period, data_json, calculated_tax, status, inspector_id)
*   `Payment` (id, taxpayer_id, amount, payment_date, declaration_id)
*   `Arrears` (id, taxpayer_id, amount, creation_date, status (`ACTIVE`, `PAID`))

## 5. Минимальный список эндпоинтов (REST API)

**AdminController (`/api/admin/**`):**
*   `POST /inspectors` - Создать нового инспектора.
*   `GET /inspectors` - Получить список всех инспекторов.
*   `GET /inspectors/{id}` - Получить инспектора по ID.
*   `PUT /inspectors/{id}` - Обновить данные инспектора.
*   `DELETE /inspectors/{id}` - Удалить/деактивировать инспектора.

**TaxpayerController (`/api/taxpayers/**`):**
*   `POST /` - Создать нового налогоплательщика.
*   `GET /` - Получить список всех налогоплательщиков.
*   `GET /{id}` - Получить налогоплательщика по ID.
*   `PUT /{id}` - Обновить данные налогоплательщика.
*   `DELETE /{id}` - Архивировать налогоплательщика.
*   `GET /search?inn=...&fio=...&companyName=...` - Поиск по параметрам.

**DeclarationController (`/api/declarations/**`):**
*   `POST /` - Подать новую декларацию.
*   `GET /{id}` - Посмотреть декларацию.
*   `PUT /{id}/status` - Изменить статус проверки (например, на `ПРОВЕРЕНА`).
*   `GET /taxpayer/{taxpayerId}` - Получить все декларации налогоплательщика.

**PaymentController (`/api/payments/**`):**
*   `POST /` - Зарегистрировать платеж.
*   `GET /taxpayer/{taxpayerId}` - Получить историю платежей налогоплательщика.
*   `GET /arrears` - Получить список всех задолженностей.
*   `GET /arrears/taxpayer/{taxpayerId}` - Получить задолженности конкретного налогоплательщика.

**AuthController (`/api/auth/**`):**
*   `POST /login` - Аутентификация пользователя, получение JWT-токена.

## 7. Архитектурные принципы и Паттерны проектирования

*   **MVC (Model-View-Controller):** Разделение логики, представления и данных (для REST API "View" будет отсутствовать или быть минимальным).
*   **Repository + Service + Controller:** Чистая архитектура для разделения ответственности слоев приложения.
*   **DTO (Data Transfer Object) + Mapper:** Для передачи данных между слоями и внешним API, избегая прямого использования сущностей.
*   **Factory / Builder:** Для создания сложных сущностей (по мере необходимости).
*   **RBAC (Role-Based Access Control):** Разграничение прав доступа на основе ролей пользователей.

## 8. Алгоритмы и Сценарии Использования Системы (DTA)

### 8.1. Сценарии для Администратора (роль `ADMIN`)

Администратор управляет учетными записями сотрудников налоговой службы.

#### 8.1.1. Вход в систему
1.  **Действие:** Администратор открывает интерфейс системы.
2.  **Шаг:** Вводит свой логин и пароль.
3.  **Эндпоинт:** `POST /api/auth/login`
4.  **Результат:** Получает JWT-токен для доступа к функциям администратора.

#### 8.1.2. Управление инспекторами
1.  **Действие:** Создание новой учетной записи для налогового инспектора.
2.  **Шаг:** Заполняет форму с данными инспектора.
3.  **Эндпоинт:** `POST /api/admin/inspectors`
4.  **Результат:** В системе создана учетная запись для инспектора с ролью `TAX_INSPECTOR`.
5.  **Действие:** Просмотр или деактивация инспектора.
6.  **Шаг:** Находит инспектора в списке и выполняет нужное действие.
7.  **Эндпоинты:** `GET /api/admin/inspectors`, `DELETE /api/admin/inspectors/{id}`.

### 8.2. Сценарии для Налогового Инспектора (роль `TAX_INSPECTOR`)

Инспектор выполняет основные операции по учету и контролю.

#### 8.2.1. Вход в систему
1.  **Действие:** Инспектор начинает рабочий день.
2.  **Шаг:** Вводит свой логин и пароль.
3.  **Эндпоинт:** `POST /api/auth/login`
4.  **Результат:** Получает JWT-токен для доступа к своему функционалу.

#### 8.2.2. Регистрация нового налогоплательщика
1.  **Действие:** В службу обратилась новая организация для постановки на учет.
2.  **Шаг:** Инспектор заполняет карточку налогоплательщика, указывая тип `LEGAL_ENTITY` и все необходимые реквизиты (ИНН, ОГРН).
3.  **Эндпоинт:** `POST /api/taxpayers`
4.  **Результат:** В реестре создан новый налогоплательщик.

#### 8.2.3. Поиск налогоплательщика
1.  **Действие:** Необходимо проверить данные по конкретному физическому лицу.
2.  **Шаг:** Инспектор использует поиск по ИНН.
3.  **Эндпоинт:** `GET /api/taxpayers/search?inn=...`
4.  **Результат:** Система отображает карточку найденного налогоплательщика.

#### 8.2.4. Прием и обработка декларации
1.  **Действие:** Налогоплательщик подал годовую декларацию.
2.  **Шаг 1 (Подача):** Инспектор загружает данные декларации в систему, привязывая ее к налогоплательщику.
3.  **Эндпоинт:** `POST /api/declarations`
4.  **Результат:** Декларация принята со статусом `ПРИНЯТА`. Система автоматически рассчитывает сумму налога.
5.  **Шаг 2 (Проверка):** Инспектор проводит камеральную проверку и подтверждает корректность данных.
6.  **Эндпоинт:** `PUT /api/declarations/{id}/status` с телом `{ "status": "ПРОВЕРЕНА" }`.
7.  **Результат:** Статус декларации обновлен. На основе рассчитанной суммы в системе сформировано налоговое обязательство.

#### 8.2.5. Регистрация платежа и контроль задолженности
1.  **Действие:** От банка поступили данные об уплате налога организацией.
2.  **Шаг 1 (Регистрация):** Инспектор находит налогоплательщика и вносит информацию о платеже.
3.  **Эндпоинт:** `POST /api/payments`
4.  **Результат:** Платеж учтен в системе.
5.  **Действие:** Проверка статуса оплаты по обязательству.
6.  **Шаг 2 (Контроль):** Система автоматически сопоставляет начисленную сумму и поступивший платеж. Если сумма меньше, формируется запись о задолженности (`Arrears`).
7.  **Эндпоинт (для просмотра):** `GET /api/payments/arrears`
8.  **Результат:** Инспектор видит список всех должников и может инициировать отправку уведомления.
